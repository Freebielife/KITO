# Внешний запуск каждые 30 минут

Статус: конфигурация подготовлена; внешний планировщик требует подключения владельцем.
GitHub запускает `update.yml` по своему расписанию `17,47 * * * *` (UTC).
Его расписание может задерживаться. Для второго независимого источника запусков используется cron-job.org.
Сборщик и публикация по-прежнему выполняются в GitHub Actions; свой сервер не нужен.

## Доступ

В GitHub создайте fine-grained personal access token:

- Resource owner: Freebielife.
- Only select repositories: KITO.
- Repository permissions: Actions — Read and write. Metadata — Read (добавляется автоматически).
- Задайте срок действия и заранее заменяйте токен до его окончания.
- Не добавляйте Contents write или доступ ко всем репозиториям.

Этот токен разрешает управление Actions в KITO, а не только запуск одного workflow.
Храните его только в защищённых настройках планировщика: не в чате, HTML, коммитах или URL.

## Задание cron-job.org

| Поле | Значение |
| --- | --- |
| Название | KITO — обновление каждые 30 минут |
| URL | `https://api.github.com/repos/Freebielife/KITO/actions/workflows/update.yml/dispatches` |
| Метод | POST |
| Расписание | Каждые полчаса, минуты 07 и 37 каждого часа |
| Часовой пояс | UTC |
| Тело запроса | `{"ref":"main"}` |
| Заголовок Accept | `application/vnd.github+json` |
| Заголовок Content-Type | `application/json` |
| Заголовок X-GitHub-Api-Version | `2026-03-10` |
| Заголовок Authorization | `Bearer ВАШ_ТОКЕН` — заменить непосредственно в настройках сервиса |

Планировщик только отправляет запрос запуска. Он не ждёт завершения сбора блокчейн-данных.
Успешный HTTP-ответ от dispatch ещё не означает успешную сборку: проверьте новый запуск
`workflow_dispatch` в https://github.com/Freebielife/KITO/actions и время `asOf` в `data/snapshot.json`.
Включите уведомление о неудачном HTTP-запросе в планировщике, если оно вам нужно.

## Проверка после подключения

1. Нажмите тестовый запуск в cron-job.org. Ожидается успешный HTTP-ответ (200 для указанной версии API).
2. Дождитесь зелёного `Refresh KITO data` в GitHub Actions с событием `workflow_dispatch`.
3. Проверьте следующий автоматический запуск. Без него настройка не считается завершённой.
4. Один раз замените `index.html` в Resistance Tools, чтобы получить новый загрузчик и кнопку обновления.
   Дальше страница самостоятельно запрашивает данные каждые пять минут, при возвращении на вкладку
   и при восстановлении сети. Кнопка «Обновить» загружает опубликованный снимок, не запускает сборщик.

Оба сервиса могут задерживать задания; точное обновление минута в минуту не гарантируется.
Если один запуск ещё идёт, GitHub ставит следующий в очередь через concurrency.
